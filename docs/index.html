portrait-webCLI

photo to VRM ● 100% local · zero egress GitHub
Choose a photo of a face to begin.

Start from a photo. The page reads the face on your device, makes a face-blendshape GLB from it, and drives a base VRM's expression blendshapes from that GLB's morphs. Optionally it moves the VRM's face shape, hair shape and colors toward the photo. The skeleton, skin weights and existing blendshapes are not changed, and the hairstyle can be re-laid as waves, curls or coils or switched to a cut preset (no new hair is added).

Stays on this device

Your photo, the face GLB made from it, and everything derived from them are processed in this page and are never sent to any server. The face model runs locally from files served with this page (nothing from a CDN). The page makes GET requests only, and the whole thing works with the network off once the page has loaded.

Approximate, not a likeness guarantee

The binding makes the VRM's expressions drivable from the face source. The shape and color matching below is a rough, measured nudge (eye size and spacing, mouth, jaw, profile depth; skin, hair, eye and brow color); an anime base will still look like an anime character.

Agent use

?vrm=male|female|URL&run=bind starts the bind as soon as a photo (or face GLB) is supplied from local disk. The photo and the face GLB are identity data and are never read from a URL (image= / face= are refused). Add &download=1 to also trigger the download.

The page sets document.body.dataset.webcliStatus (idle | running | done | error) and window.__webcli_result = { ok, op: 'bind', artifact: { mime, name, size, dataUrl }, error, meta }. window.__portrait.run({ vrm, image, face, look, shape, hairShape, hairStyle, facialHair, bald }) takes 'male' (default), 'female', a URL or a File for vrm, and a File (or Blob or bytes) for image / face. Hooks: data-testid photo-input, face-input, vrm-input, vrm-url, bind, download, result, status.
